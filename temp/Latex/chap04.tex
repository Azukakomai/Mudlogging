\chapter{PROTOTYPE AND PRODUCT DESIGN}

\section{System Requirements Specification}

To ensure the developed decision support system directly resolves the operational, computational, and regulatory bottlenecks identified in Chapter~2, rigorous requirements engineering was conducted. The system specifications are structured into Functional Requirements (FR) and Non-Functional Requirements (NFR):

\subsection{Functional Requirements (FR)}
\begin{itemize}
    \item \textbf{FR-01 (Multi-Format Ingestion):} Ingest mud logging files across standard delimited ASCII (\texttt{.csv}, \texttt{.txt}), spreadsheet (\texttt{.xlsx}), and Log ASCII Standard (\texttt{.las} v1.2/v2.0) formats, automatically isolating tabular numeric matrices from variable company headers and rig comments.
    \item \textbf{FR-02 (Data Normalization and Cleansing):} Validate, align, and clean chromatographic gas curves ($C_1$ through $nC_5$ and $TG$) against continuous Measured Depth ($MD$) indices, systematically handling non-numeric tokens, null values, and out-of-order depth rows.
    \item \textbf{FR-03 (Automated Multi-Ratio Computation):} Automatically compute 16 derived petrophysical indicators from input gas curves upon file upload without requiring manual scripting.
    \item \textbf{FR-04 (Deterministic Fluid Zone Forecasting):} Apply closed-form, deterministic majority-voting decision logic to classify depth increments into categorical fluid regimes: \textbf{Gas Pay Zone}, \textbf{Oil Pay Zone}, or \textbf{Non-Bearing Sand / No Show}.
    \item \textbf{FR-05 (Multi-Track Depth-Synchronized Visualization):} Render continuous vertical area strip charts for all raw gas fractions, computed indicators, and fluid zone classifications across dedicated tracks, featuring synchronized scrolling, depth zooming, and cursor hover crosshairs adhering to API RP 31A and SPWLA wellsite mud logging standards.
    \item \textbf{FR-06 (Dynamic Schema and Formula Management):} Provide interactive modal interfaces allowing users to toggle column visibility, create custom user-defined tracks, modify mathematical expressions with live sample evaluation, and calibrate classification cutoff thresholds with instantaneous dashboard updates.
    \item \textbf{FR-07 (Data Export and Reporting):} Enable the export of computed petrophysical curves and fluid classification results in standardized tabular formats (\texttt{.csv}) for downstream reporting and archiving.
\end{itemize}

\subsection{Non-Functional Requirements (NFR)}
\begin{itemize}
    \item \textbf{NFR-01 (Computational Latency):} The end-to-end execution pipeline (file ingestion, ratio calculation, and multi-track visual rendering) must complete in under 5.0 seconds for well trajectories exceeding 3,000 meters.
    \item \textbf{NFR-02 (Mathematical Traceability and PRMS Auditability):} All calculations must operate on explicit, transparent, closed-form formulas with zero non-traceable parameters, ensuring complete compliance with SPE PRMS Chapter 4 reserve certification mandates \citep{ref3}.
    \item \textbf{NFR-03 (Usability and Workflow Learnability):} The interface must deliver an intuitive single-click operational workflow accessible without specialized training, targeting a standardized System Usability Scale (SUS) score of $S_{\text{SUS}} \ge 68.0/100$.
    \item \textbf{NFR-04 (Cross-Platform Accessibility and Zero Licensing Overhead):} The application must run on open-source Python technologies, deployed serverless on the web to eliminate multi-thousand-dollar annual commercial licensing constraints and local installation dependencies \citep{wood2020}.
\end{itemize}

\section{Decoupled Three-Tier System Architecture}

To achieve high modularity, maintainability, and operational responsiveness, the software is structured into a decoupled three-tier architecture, as illustrated in the system design:
\begin{enumerate}
    \item \textbf{Data Parsing and Ingestion Layer:} Responsible for file decoding, encoding detection, header stripping, column normalization, type casting, and structured matrix generation.
    \item \textbf{Deterministic Logic Engine Layer:} Implements petrophysical formulas, maintains the declarative parameter dependency graph, vectorizes numerical operations, executes boundary-evaluation rules, and performs majority-voting fluid classification.
    \item \textbf{Presentation and Dashboard Layer:} Provides an interactive, reactive web user interface built with Dash and Plotly WebGL, delivering responsive layout controls, synchronized multi-track visual rendering, and modal management dialogs.
\end{enumerate}

\section{Data Parsing and Ingestion Pipeline Design}

Mud logging files generated by field logging units are notoriously heterogeneous, featuring variable header structures, diverse column naming conventions, operator remarks, and missing data points. The ingestion subsystem is designed around a multi-stage automated pipeline:

\subsection{Format Identification and Header Isolation}
The parser scans incoming data streams line-by-line within an initial 100-line inspection window. By matching token markers (such as \texttt{\char`~A} in LAS files, or column tokens like \texttt{DEPTH}, \texttt{METRES}, \texttt{MD}, and \texttt{C1}), the parser automatically identifies the boundary where tabular column headers begin, discarding non-tabular operator comments and metadata lines above that boundary.

\subsection{Column Aliasing and Standardization Dictionary}
Different mud logging contractors utilize distinct column nomenclatures for identical gas channels. To ensure seamless ingestion, the design incorporates a comprehensive aliasing dictionary that translates heterogeneous header names into standardized internal identifiers:
\begin{itemize}
    \item Depth: \texttt{['DEP', 'DEPTH', 'DEPTH\_M', 'DEPTH\_METRES', 'MD']} $\rightarrow$ \texttt{DEPTH}
    \item Methane ($C_1$): \texttt{['CH4', 'METHANE', 'C1']} $\rightarrow$ \texttt{C1}
    \item Ethane ($C_2$): \texttt{['C2H6', 'ETHANE', 'C2']} $\rightarrow$ \texttt{C2}
    \item Propane ($C_3$): \texttt{['C3H8', 'PROPANE', 'C3']} $\rightarrow$ \texttt{C3}
    \item Iso-butane ($iC_4$): \texttt{['I-C4', 'ISOBUTANE', 'I\_C4', 'IC4']} $\rightarrow$ \texttt{IC4}
    \item Normal-butane ($nC_4$): \texttt{['N-C4', 'NORMALBUTANE', 'N\_C4', 'NC4']} $\rightarrow$ \texttt{NC4}
    \item Iso-pentane ($iC_5$): \texttt{['I-C5', 'ISOPENTANE', 'I\_C5', 'IC5']} $\rightarrow$ \texttt{IC5}
    \item Normal-pentane ($nC_5$): \texttt{['N-C5', 'NORMALPENTANE', 'N\_C5', 'NC5']} $\rightarrow$ \texttt{NC5}
    \item Total Gas ($TG$): \texttt{['TOTAL\_GAS', 'GAS', 'TOT\_GAS', 'TG']} $\rightarrow$ \texttt{TG}
\end{itemize}

\subsection{Type Casting, Cleansing, and Depth Sorting}
Missing columns are initialized with zero floats ($0.0$). Non-numeric values and text artifacts are coerced to numeric floats with null replacement. The resulting matrix is sorted strictly in ascending order by Measured Depth ($MD$), generating a continuous, monotonically increasing depth profile.

\section{Deterministic Petrophysical Logic Engine and DAG Design}

To ensure flexibility across diverse geological basins without requiring code-level modifications, the computation engine represents petrophysical variables, mathematical formulas, and decision boundaries as a \textbf{declarative directed acyclic graph (DAG)}:
\begin{itemize}
    \item \textbf{Vertices} represent physical data channels, encompassing measured gas curves ($C_1$, $C_2$, $C_3$, $iC_4$, $nC_4$, $iC_5$, $nC_5$, $TG$), derived ratio parameters ($W_h$, $B_h$, $C_h$, $R_1 \dots R_5$, $DR$, $I_{\text{carbon}}$), composite indicators ($GOW, WBS, GOR$), and categorical fluid classification states.
    \item \textbf{Edges} define mathematical dependencies, functional transformations, and boundary decision logic connecting parent curves to downstream petrophysical indicators.
\end{itemize}

\subsection{Safe Numerical Division and Vectorization}
In drilling operations, individual gas fractions can drop to $0.0\text{ ppm}$. Standard division operations would generate fatal \texttt{ZeroDivisionError} or infinity values. The engine implements safe numerical vector operations:
\begin{equation}
    \text{div}(A, B) = \begin{cases} \frac{A}{B}, & \text{if } B > 0 \\ \text{NaN}, & \text{if } B \le 0 \end{cases}
\end{equation}
Vectorizing these operations across contiguous NumPy arrays ensures ultra-low computational latency.

\subsection{Majority-Voting Decision Tree Architecture}
At each discrete depth increment, the engine executes a three-stage decision process:
\begin{enumerate}
    \item \textbf{Baseline Show Detection Gate:} If total gas fails to breach the baseline noise floor ($TG < 300\text{ ppm}$ and $C_1 < 200\text{ ppm}$), the formation is immediately classified as \textbf{No Show / Barren Rock}, preventing division artifacts in tight formations.
    \item \textbf{Multi-Indicator Rule Evaluation:} Intervals breaching the baseline gate collect independent classification votes ($v \in \{\text{Gas}, \text{Oil}, \text{Water}\}$) from 8 distinct petrophysical indicators (Haworth $W_h, B_h, C_h$, Dryness, Pixler $R_1$, $WBS$, $GOR$, and $GOW$).
    \item \textbf{Majority-Vote Consensus:} The final fluid regime $\hat{y}_i$ is assigned to the class receiving the maximum aggregate vote:
    \begin{equation}
        \hat{y}_i = \operatorname*{arg\,max}_{c \in \{\text{Gas}, \text{Oil}, \text{Water}\}} \left( \sum_{m=1}^{M} w_m \cdot \mathbb{I}\left(f_m(\mathbf{x}_i) = c\right) \right)
    \end{equation}
    where $w_m = 1.0$ by default.
\end{enumerate}

\subsection{Discrete Columnar Strip Log Layout}
Rather than grouping multiple curves into crowded multi-line overlays that obscure crossover nuances, each parameter is assigned a dedicated vertical strip log column (Figure~\ref{fig:design_main_tracks}). This includes raw alkane fractions ($C_1$--$nC_5, TG$), Pixler ratios ($R_1$--$R_4$, $\text{Ratio } iC_4, \text{Ratio } nC_4$), fluid indicators ($DR, I_{\text{carbon}}, W_h\%, B_h, C_h$), composite multipliers ($GOW, GOW/TG, WBS, GOR$), and the categorical $Zone$ track.

\subsection{Color-Coded Shaded Area Fills and Visual Envelopes}
Curves are rendered with high-contrast translucent shaded area fills from the baseline:
\begin{itemize}
    \item \textit{Emerald Green Fills:} Applied to individual raw alkane gas fractions ($C_1$--$nC_5, TG$) and Pixler diagnostic ratios ($R_1$--$R_4$, $\text{Ratio } iC_4, \text{Ratio } nC_4$).
    \item \textit{Vibrant Cyan/Blue Fills:} Applied to petrophysical fluid character indicators (Dryness $DR$, $I_{\text{carbon}}$, $W_h\%$, $B_h$, $C_h$), clearly separating fluid composition from volumetric gas magnitude.
    \item \textit{Warm Orange Fills:} Applied to composite multipliers and productivity indicators ($GOW, GOW/TG, WBS, GOR$).
    \item \textit{Categorical Regime Banding:} The rightmost $Zone$ track displays discrete horizontal colored blocks indicating the winning majority-vote fluid facies (Green for Gas Pay, Red for Oil Pay, Blue for Water, and Slate Gray for Barren/No-Show).
\end{itemize}

\subsection{The 25\% Column Normalization Rule for 100\% Viewport Width Containment}
To prevent visual crowding while ensuring all 23 active tracks fit dynamically within 100\% of the screen width without horizontal scrollbars, a dynamic \textbf{25\% Column Normalization Rule} is designed into the layout engine:
\begin{equation}
    \omega_i = \min\left(\frac{w_i^{\text{base}}}{\sum_{j=1}^{K} w_j^{\text{base}}}, 0.25\right), \quad \text{with} \quad \sum_{i=1}^{K} \omega_i = 1.0
\end{equation}
Any single composite track is capped at a maximum of 25\% of viewport width, while single-curve tracks have a minimum width floor ($w_i \ge 0.05 \cdot W_{\text{viewport}}$), redistributing remaining width dynamically.

\subsection{Typography and Numerical Scaling Hierarchy}
To ensure legibility under variable lighting on ruggedized field laptops, track headers are enlarged to 13–14\,pt bold weights, depth markers utilize high-contrast monospace typography, and hover crosshair tooltips display real-time depth and multi-curve values prominently.

As shown in Figure~\ref{fig:design_columns_manager}, the column manager provides a three-tab interface:
\begin{enumerate}

    \item \textbf{Add New Column:} Interface to construct custom user-defined tracks on the fly, specifying column identifiers, physical units, color pickers, scale type ($\log$ vs. $\text{linear}$), and mathematical expressions using quick-insert variable chips.

\chapter{PRODUCT IMPLEMENTATION AND CONSTRUCTION}

\section{Software Module Architecture and Engineering Strategy}

The implementation of the Gas While Drilling (GWD) decision support system follows the decoupled three-tier architectural design established in Chapter~4. The codebase is organized into four dedicated Python modules, ensuring modularity, strict separation of concerns, and reproducible scientific computing:

\begin{enumerate}
    \item \texttt{parser.py}: The Data Ingestion and Normalization Layer, responsible for parsing multi-format well logs, stripping metadata headers, mapping heterogeneous column aliases, type casting, and sorting depth records.
    \item \texttt{engine.py}: The Petrophysical Calculation and Deterministic Logic Engine, encapsulating the 16 derived indicator formulas, safe numerical division routines, dynamic DAG evaluation, and rule-based majority-voting zone classification.
    \item \texttt{app.py}: The Reactive Presentation and Dashboard Layer, constructed using Dash, Bootstrap components, and Plotly WebGL to manage user interactions, modal dialogs, asynchronous state updates, and multi-track visual rendering.
    \item \texttt{evaluator.py}: The Automated Verification and Benchmarking Suite, generating synthetic test arrays, running unit assertions, and calculating classification metrics and confusion matrices.
\end{enumerate}

\section{Ingestion and Normalization Implementation (\texttt{parser.py})}

The \texttt{parser.py} module implements the automated data ingestion pipeline via the primary function \texttt{parse\_mudlog\_file(file\_path\_or\_buffer)}. The implementation proceeds across four sequential algorithmic stages:

\subsection{Header Isolation and Metadata Stripping}
To isolate the tabular data matrix from non-standard company headers and rig operator remarks, the parser inspects the incoming file stream line-by-line:
\begin{lstlisting}[language=Python, caption={Header isolation algorithm in \texttt{parser.py}}]
header_idx = 0
for i, line in enumerate(lines[:100]):
    line_upper = line.upper()
    if 'DEPTH' in line_upper or 'METRES' in line_upper or 'C1' in line_upper or '~A' in line_upper:
        header_idx = i
        break
content = "".join(lines[header_idx:])
df_raw = pd.read_csv(io.StringIO(content), sep=None, engine='python')
\end{lstlisting}
This routine automatically scans up to 100 header lines, identifies the first occurrence of standard depth or gas tokens, and initiates CSV parsing directly from the tabular boundary.

\subsection{Column Mapping and Standardization}
Heterogeneous header naming conventions across different logging service companies are normalized using a global translation dictionary:
\begin{lstlisting}[language=Python, caption={Column standardization mapping in \texttt{parser.py}}]
column_mapping = {
    'DEP': 'DEPTH', 'DEPTH_M': 'DEPTH', 'DEPTH_METRES': 'DEPTH', 'MD': 'DEPTH',
    'CH4': 'C1', 'METHANE': 'C1',
    'C2H6': 'C2', 'ETHANE': 'C2',
    'C3H8': 'C3', 'PROPANE': 'C3',
    'I-C4': 'IC4', 'ISOBUTANE': 'IC4', 'I_C4': 'IC4',
    'N-C4': 'NC4', 'NORMALBUTANE': 'NC4', 'N_C4': 'NC4',
    'I-C5': 'IC5', 'ISOPENTANE': 'IC5', 'I_C5': 'IC5',
    'N-C5': 'NC5', 'NORMALPENTANE': 'NC5', 'N_C5': 'NC5',
    'TOTAL_GAS': 'TG', 'GAS': 'TG', 'TOT_GAS': 'TG'
}
df_raw = df_raw.rename(columns=column_mapping)
\end{lstlisting}

\subsection{Type Casting, Cleansing, and Depth Ordering}
All required channels are validated. Missing gas fractions are initialized with $0.0$, invalid non-numeric strings are coerced to numeric floats (\texttt{errors='coerce'}), null entries are filled with $0.0$, and the DataFrame is sorted strictly in ascending depth order:
\begin{lstlisting}[language=Python, caption={Data cleansing and type casting in \texttt{parser.py}}]
for col in ['DEPTH', 'C1', 'C2', 'C3', 'IC4', 'NC4', 'IC5', 'NC5']:
    if col not in df_raw.columns:
        df_raw[col] = 0.0
    df_raw[col] = pd.to_numeric(df_raw[col], errors='coerce').fillna(0.0)

df_clean = df_raw.dropna(subset=['DEPTH']).sort_values(by='DEPTH').reset_index(drop=True)
\end{lstlisting}

\section{Vectorized Deterministic Calculation Pipeline (\texttt{engine.py})}

The \texttt{engine.py} module implements the mathematical formulations and deterministic decision logic defined in Chapter~3 and Chapter~4.

\subsection{Safe Numerical Division (\texttt{\_safe\_div})}
To prevent runtime crashes and invalid infinity values caused by zero-gas readings, division is wrapped in a vectorized safe-division routine:
\begin{lstlisting}[language=Python, caption={Vectorized safe division in \texttt{engine.py}}]
def _safe_div(numerator, denominator):
    num = np.asarray(numerator, dtype=np.float64)
    den = np.asarray(denominator, dtype=np.float64)
    with np.errstate(divide='ignore', invalid='ignore'):
        result = np.where(den > 0.0, num / den, np.nan)
    return result
\end{lstlisting}

\subsection{16-Indicator Parameter Derivation (\texttt{compute\_all})}
Given a cleaned DataFrame, \texttt{compute\_all(df)} calculates the full matrix of 16 petrophysical parameters using vectorized operations:
\begin{lstlisting}[language=Python, caption={Vectorized petrophysical parameter calculation in \texttt{engine.py}}]
# 1. Pixler Ratios
df['R1'] = _safe_div(df['C1'], df['C2'])
df['R2'] = _safe_div(df['C1'], df['C3'])
df['R3'] = _safe_div(df['C2'], df['C3'])
df['Ratio_iC4'] = _safe_div(df['C1'], df['IC4'])
df['Ratio_nC4'] = _safe_div(df['C1'], df['NC4'])

# 2. Total Gas & Gas Dryness
c_sum = df['C1'] + df['C2'] + df['C3'] + df['IC4'] + df['NC4'] + df['IC5'] + df['NC5']
df['TG'] = np.where(df.get('TG', 0) > 0, df['TG'], c_sum)
df['Dryness'] = _safe_div(df['C1'], df['TG'])

# 3. Carbon Index
c_weighted = (df['C1'] + 2*df['C2'] + 3*df['C3'] + 4*df['IC4'] + 
              4*df['NC4'] + 5*df['IC5'] + 5*df['NC5'])
df['Ci'] = _safe_div(df['TG'], c_weighted)

# 4. Haworth Show Evaluation Ratios
heavy_gas = df['C2'] + df['C3'] + df['IC4'] + df['NC4'] + df['IC5'] + df['NC5']
df['Wh'] = _safe_div(heavy_gas, df['TG']) * 100.0
df['Bh'] = _safe_div(df['C1'] + df['C2'], df['C3'] + df['IC4'] + df['NC4'] + df['IC5'] + df['NC5'])
df['Ch'] = _safe_div(df['IC4'] + df['NC4'] + df['IC5'] + df['NC5'], df['C3'])

# 5. Composite Indicators & Whittaker Score
df['GOW'] = _safe_div(heavy_gas * df['TG'], df['TG'])
df['GOW_noTG'] = _safe_div(df['C1'] * df['C2'], df['C3'] * df['NC4'] * df['NC5'])
log_bh = np.where(df['Bh'] > 0, np.log10(df['Bh']), np.nan)
log_wh = np.where(df['Wh'] > 0, np.log10(df['Wh']), np.nan)
df['WBS'] = (log_bh - 0.903) / 2.097 - (log_wh / 2.0)
df['GOR'] = np.where(df['Wh'] > 0, 1000.0 / (df['Wh'] + 1e-5), np.nan)
\end{lstlisting}

\subsection{Deterministic Majority-Voting Zone Classification (\texttt{\_classify\_zones})}
The classification routine evaluates the multi-parameter matrix row-by-row, tallying independent votes for Gas, Oil, and Water pay:
\begin{lstlisting}[language=Python, caption={Majority-voting zone classification in \texttt{engine.py}}]
def _classify_zones(df, thresholds):
    zones = []
    for _, row in df.iterrows():
        tg, c1 = row.get('TG', 0.0), row.get('C1', 0.0)
        # Noise Floor Filter
        if tg < thresholds['tg_floor'] and c1 < thresholds['c1_floor']:
            zones.append('No Show')
            continue
            
        votes = {'Gas': 0, 'Oil': 0, 'Water': 0}
        # Haworth Wh Vote
        wh = row.get('Wh', np.nan)
        if pd.notna(wh):
            if thresholds['wh_gas_min'] <= wh < thresholds['wh_gas_max']: votes['Gas'] += 1
            elif thresholds['wh_gas_max'] <= wh < thresholds['wh_oil_max']: votes['Oil'] += 1
            else: votes['Water'] += 1
            
        # Haworth Bh Vote
        bh = row.get('Bh', np.nan)
        if pd.notna(bh):
            if bh > thresholds['bh_gas_min']: votes['Gas'] += 1
            elif bh >= thresholds['bh_oil_min']: votes['Oil'] += 1
            else: votes['Water'] += 1
            
        # Pixler R1 Vote
        r1 = row.get('R1', np.nan)
        if pd.notna(r1):
            if r1 >= thresholds['r1_gas_min']: votes['Gas'] += 1
            elif r1 >= thresholds['r1_oil_min']: votes['Oil'] += 1
            else: votes['Water'] += 1
            
        # Tally majority vote
        best_zone = max(votes, key=votes.get)
        zones.append(best_zone if votes[best_zone] > 0 else 'No Show')
    return zones
\end{lstlisting}

The \texttt{app.py} module constructs the single-page web dashboard using Dash, Plotly, and Dash Bootstrap Components.

\subsection{Multi-Track Plotly Chart Builder (\texttt{render\_full\_continuous\_tracks})}
The visualization engine generates a 23-column continuous strip log using \texttt{plotly.subplots.make\_subplots}:
\begin{lstlisting}[language=Python, caption={Plotly multi-track chart generation in \texttt{app.py}}]
fig = make_subplots(
    rows=1, cols=len(active_tracks) + 1,
    shared_yaxes=True,
    horizontal_spacing=0.003,
    column_widths=normalized_widths
)
for col_idx, spec in enumerate(active_tracks, start=1):
    fig.add_trace(
        go.Scatter(
            x=df[spec['col']], y=df['DEPTH'],
            mode='lines', line=dict(color=spec['color'], width=1.2),
            fill='tozerox', fillcolor=spec['fill_color'],
            name=spec['label']
        ),
        row=1, col=col_idx
    )
fig.update_yaxes(autorange='reversed', title_text='Measured Depth (m)', row=1, col=1)
\end{lstlisting}
The Y-axis is inverted (\texttt{autorange='reversed'}) so depth begins at $0\text{ m}$ at the top and increases downwards, matching standard well logging orientation.

\section{Automated Verification and Benchmarking Suite (\texttt{evaluator.py})}

The \texttt{evaluator.py} module implements automated unit testing, synthetic dataset generation, and classification benchmarking:
\begin{itemize}
    \item Generates synthetic benchmark well profiles with known analytical fluid regimes to verify ratio math.
    \item Constructs multi-class confusion matrices across Gas Pay, Oil Pay, and Non-Bearing intervals.
    \item Calculates Precision, Recall, Class $F_1$, Macro-$F_1$, and Overall Accuracy.
\end{itemize}

\section{Serverless Cloud Deployment and Open-Source Packaging}

To fulfill NFR-04 and ensure zero-installation operational availability, the software is deployed to production using the \textbf{Vercel} serverless cloud platform:
\begin{enumerate}
    \item \textbf{Serverless Routing (\texttt{vercel.json} \& \texttt{api/index.py}):} Incoming HTTP requests route to lightweight serverless Python functions that execute computations in memory on demand, terminating upon completion.
    \item \textbf{Edge Network Static Delivery:} Frontend JavaScript assets, stylesheets, and WebGL renderers are cached globally across Vercel's Edge Network for sub-second delivery.
    \item \textbf{Version Pinned Manifest (\texttt{requirements.txt}):} Core dependencies (\texttt{dash}, \texttt{dash-bootstrap-components}, \texttt{plotly}, \texttt{pandas}, \texttt{numpy}, \texttt{openpyxl}) are pinned to guarantee cross-platform execution.
    \item \textbf{Open-Source GitHub Repository:} The codebase is published on GitHub with setup instructions, sample datasets, and full documentation to support community verification.
\end{enumerate}
